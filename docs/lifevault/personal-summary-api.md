# ช่องอ่านสรุปการเงินส่วนตัวให้ Life Vault

ช่องอ่านอย่างเดียว 1 ช่อง ให้เบราว์เซอร์ของเจ้าของที่เปิด Life Vault ดึง "ภาพสิ้นเดือน" 5 ตัวเลขจาก Fintrack โดยตรง
ตัวเลขไม่ผ่านเซิร์ฟเวอร์ของ Vault (Life Vault DEC-26 · OQ-7) · โค้ด: `lifevault-summary.mjs` · เทส: `node lifevault-summary.test.mjs`

เจ้าของเคาะแบบ 9 ต.ค. 2569

## คำขอ

```
GET /integrations/lifevault/personal-summary[?month=YYYY-MM]
Origin: <ที่อยู่เว็บของ Vault>
Authorization: Bearer <กุญแจ Life Vault>
```

- `month` ไม่ส่ง = เดือนล่าสุดที่จบแล้ว (ตามเวลาไทย) · ส่งเดือนนี้ได้ จะได้ภาพ ณ วันนี้ · เดือนในอนาคต = 400
- ไม่ใช้คุกกี้ ไม่ต้องส่ง `credentials: 'include'`

## คำตอบ (200)

```json
{
  "month": "2026-09",
  "as_of": "2026-09-30",
  "net_worth_satang": 0,
  "savings_rate_pct": 0,
  "debt_satang": 0,
  "reserve_months": 0,
  "expense_satang": 0
}
```

เงินเป็นจำนวนเต็มสตางค์ · อัตราและจำนวนเดือนเป็นทศนิยม 1 ตำแหน่ง · มีแค่ 7 ช่องนี้ (ตัวเลขข้างบนเป็นตัวอย่างรูปแบบ ไม่ใช่ข้อมูลจริง)

| ช่อง | นิยาม |
|---|---|
| `as_of` | วันสิ้นเดือนของ `month` หรือวันนี้ถ้าเดือนยังไม่จบ |
| `net_worth_satang` | ยอด ณ `as_of` ของกระเป๋า "ส่วนตัว" ที่ยังเปิดใช้ทุกใบรวมกัน (บัตรเครดิตเป็นค่าลบ) |
| `debt_satang` | ยอดค้างบัตรเครดิตส่วนตัว ณ `as_of` |
| `expense_satang` | รายจ่ายที่ตั้งเป็น "ส่วนตัว" ของเดือนนั้น ไม่นับรายการร่างและการโอนระหว่างกระเป๋า |
| `savings_rate_pct` | (รายรับ − รายจ่าย) ÷ รายรับ × 100 ของเดือนนั้น · ไม่มีรายรับ = 0 · ต่ำสุด −999 |
| `reserve_months` | เงินสดกับเงินฝากส่วนตัว ณ `as_of` ÷ รายจ่ายเฉลี่ย 3 เดือนที่จบที่ `month` · ไม่มีรายจ่าย = 0 · สูงสุด 999 |

กติกาการโอน: ร้าน → ส่วนตัว นับเป็นรายรับส่วนตัว · ส่วนตัว → ร้าน ไม่นับเป็นรายจ่าย · ส่วนตัว ↔ ส่วนตัว ไม่นับทั้งสองทาง

ยอด ณ `as_of` คิดจากยอดปัจจุบันของกระเป๋า ถอยรายการที่ลงวันที่หลัง `as_of` ออก

### ข้อจำกัดที่ต้องรู้

- Fintrack ไม่มีเงินกู้ (บ้าน รถ สินเชื่อ) และไม่มีทรัพย์สินอื่น (ที่ดิน ทอง กองทุน หุ้น) — หนี้ = บัตรเครดิตเท่านั้น · มูลค่าสุทธิ = เงินสด + เงินฝาก − ยอดค้างบัตร
- ตัวเลขถูกเท่าที่เจ้าของลงรายการส่วนตัวใน Fintrack
- กระเป๋าส่วนตัวที่ปิดใช้แล้วไม่ถูกนับ แม้ในเดือนย้อนหลังที่ตอนนั้นยังเปิดอยู่

## คำตอบเมื่อไม่ผ่าน

| รหัส | เมื่อ |
|---|---|
| 404 | ยังไม่ตั้งค่าครบ 3 ตัว (ช่องปิดอยู่) |
| 403 | `Origin` ไม่ตรงกับ Vault · หรือบัญชีที่ผูกกับกุญแจไม่ใช่ผู้ดูแลที่ยังใช้งาน |
| 401 | ไม่มีกุญแจหรือกุญแจผิด |
| 400 | `month` ผิดรูปแบบหรือเป็นเดือนในอนาคต |
| 405 / 429 | ไม่ใช่ GET · เรียกถี่เกิน 20 ครั้งต่อนาทีต่อ IP |

Vault แสดง 401 และ 403 ว่า "ยังไม่ได้เข้าระบบ Fintrack" อยู่แล้ว

## ใครเรียกได้

- เฉพาะผู้ถือกุญแจ Life Vault และต้องเรียกจากที่อยู่เว็บของ Vault
- กุญแจผูกกับบัญชีเจ้าของ 1 บัญชี (ต้องเป็น admin และยัง active) ข้อมูลที่ได้คือของ workspace ของบัญชีนั้น
- กุญแจนี้เข้า route อื่นของ Fintrack ไม่ได้ · กุญแจของ LINE bot, HR OS และ JWT ของผู้ใช้เข้าช่องนี้ไม่ได้

## สิ่งที่ไม่ส่ง

รายการเดินบัญชีรายตัว · ชื่อกระเป๋า · เลขบัญชี · ชื่อร้านค้าหรือคู่ค้า · ตัวเลขของกิจการ · ข้อมูลพนักงาน

## เปิดใช้ (เจ้าของสั่งตอน deploy · INTEGRATION_POLICY)

ตั้ง secret ของ worker `fintrack-api` 3 ตัว ช่องปิดอยู่ (404) จนกว่าจะครบ:

| secret | ค่า |
|---|---|
| `LIFEVAULT_TOKEN` | กุญแจสุ่มยาว สร้างใหม่เฉพาะ Vault ห้ามใช้ซ้ำกับระบบอื่น ห้ามพิมพ์ลงแชทหรือเอกสาร |
| `LIFEVAULT_USER_ID` | id ของบัญชีเจ้าของใน Fintrack |
| `LIFEVAULT_ORIGIN` | ที่อยู่เว็บของ Vault เช่น `https://<โดเมนของ Vault>` (ได้ 1 ที่อยู่) |

- ก่อน `wrangler deploy` เทียบโค้ด prod ปัจจุบันกับ `worker.js` ก่อน (worker เป็น hand-maintained)
- ไม่แตะ `SERVICE_TOKEN` `SERVICE_USER_ID` `HROS_*` `FINTRACK_TOKEN` `functions/*` และไม่มี migration
- **rollback / เพิกถอนกุญแจ:** ลบ `LIFEVAULT_TOKEN` ช่องกลับเป็น 404 ทันที ของเดิมไม่ต้องแก้กลับ

## สิ่งที่ฝั่ง Life Vault ต้องปรับ (`pullFintrack` ใน `src/lib/stats.ts`)

1. ส่ง `Authorization: Bearer <กุญแจ>` แทน `credentials: 'include'` — Fintrack ไม่มีคุกกี้ การเข้าระบบอยู่ใน localStorage ของหน้าเว็บ Fintrack ซึ่งเว็บอื่นอ่านไม่ได้
2. มีที่ให้เจ้าของวางกุญแจครั้งเดียว แล้วเก็บแบบเข้ารหัสในคลัง (เซิร์ฟเวอร์ของ Vault ไม่เห็นกุญแจ)
3. ชื่อช่องในคำตอบตรงกับที่ `pullFintrack` อ่านอยู่แล้ว ไม่ต้องแก้ · `?month=` เป็นทางเลือก
